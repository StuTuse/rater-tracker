# 1.0.3 常驻提醒与登录保持

2026-10-22～23；Windows 1.0.3，Android 1.0.3 / code12。规则1.3、JSON1、作者和原Android证书保持。主工作区main统一负责原生通知、共享会话与设置、检查和发布，没有派遣会话或使用个人账号。

## 原因与改动

通知原来已经使用Android原生AlarmManager及NotificationManager，并非仅浏览器通知。增加用户要求的原生前台服务：开启提醒时默认同时启用“常驻提醒服务”，可独立关闭；显示低打扰的持续状态通知，START_STICKY，移除页面任务不主动停止。服务每30秒维护心跳并检查当前10／11点时段；原生闹钟仍负责休眠唤醒，不使用永久唤醒锁或持续网络请求。总开关关闭或通知权限不可用时停止服务。

Android14+如实声明specialUse及用途，没有伪装成音乐播放或定位。当前为侧载APK；以后若提交Google Play，还需履行其前台服务用途申报和审核。系统强停、关机、停止活动应用、关闭卓易通宿主仍可终止服务；不能承诺永不被杀。服务和系统闹钟共同工作，不将WebView计时器作为后台投递机制。

新增立即测试通知、一分钟后台测试、刷新状态和渠道设置入口，显示权限、精确调度、服务、下次计划及最近提交阶段。测试不消耗每日文案轮换和收据；“已提交系统”不代表用户已看到。新建提醒渠道默认高重要性；Android不允许应用提高已有渠道的重要性，因此保留旧渠道和用户选择，提供横幅设置入口。

云端2026-10-23实际回读发现MaxDevice=1，即另一设备登录会踢出旧会话；RefreshTokenExpiresIn已为2592000秒，AccessTokenExpiresIn为7200秒。本轮按用户需求以ModifyClient仅调整为MaxDevice=10，并明确保持上述有效期，随后DescribeClient回读相符。脱敏配置见[auth-client-policy.json](../cloud/auth-client-policy.json)，不含密钥。已被撤销的旧凭证不能由客户端复活，可能需要重新登录一次。

共享会话优先恢复已加密保存的SDK缓存，避免每次冷启动额外轮换；setSession或续期返回的新凭证立即串行落盘。SDK清空缓存时可用长期凭证重建；通用401、缺缓存及网络失败不永久标记为需要密码，明确长期凭证撤销才要求重新登录。保持原30天无用户活动再认证规则；实际使用延续窗口，后台同步不延长闲置。身份始终核对同一UID，不保存密码、不绕过服务端吊销。

- Windows最终打包程序：61＋42＋11项回归通过，临时运行目录与ASAR摘要一致；使用独立虚构数据目录。
- Android原生仪器：14项通过，包含真实前台服务、FLAG_FOREGROUND_SERVICE／ONGOING、心跳、关闭服务、立即通知与延时PendingIntent；原11项提醒／权限／安全区检查保留。
- 专用RaterSigningAcceptance AVD：8项常驻／后台专项通过；实际系统通知栏截图中同时看到“提醒服务正在运行”和“提醒通道测试”。关闭页面一分钟后由原生接收器发布测试通知，回到页面读取实际投递时间；总开关关闭后服务停止。
- 真实CloudBase：新建虚构账号、两个独立进程设备各自登录后再轮流恢复，访问到期及29天本地活动时间模拟，6个阶段通过；各阶段只读取空云端，没有写入业务。Android Keystore真实服务专项8项通过：登录、加密保存、两次杀进程免密恢复、访问到期续期、29天保持、31天闲置再认证及清理凭证。测试账号已删除。
- 最终原签名APK：从1.0.2覆盖到1.0.3，10项原生操作通过，保留已有虚构记录、实际键盘输入自动保存、重启保留及关闭WebView调试。Windows70个／Android62个应用源码逐文件与最终ASAR／APK一致。
- 最终正式APK另做4项服务实测：通过真实设置开启、退出页面后保持前台、系统通知记录和通知栏同时有正式包服务／测试卡片、设置关闭后停止。原生控件定位初次没有向上滚动而找不到总开关，修正双向滚动后完整重验通过；按精确组件区分正式包与调试包。此脚本结束将专用AVD正式包提醒关闭。

初次设备测试用完整文案精确定位带说明的span失败，改为定位对应checkbox后通过；第二次停服务请求用了过时revision而被状态保护拒绝，改为点击实际设置开关后通过，未为测试削弱版本保护。构建、虚构凭证、截图和日志位于忽略目录，不入源码仓库。
