## 1. 已确定的需求

- **手机保留底部导航；平板左侧导航，整体排布接近电脑。** 第一轮的手机侧栏／顶栏候选取消，不再要求重新选择。
- 评分模块再适当缩小，去掉「未记录」「5–15 XP」常驻字样，给当前任务和任务进度留出空间；空白与0星在数据和交互上仍需区分。
- 保留黄色主色、少量绿色辅助、手绘素材风格，统一精简空白、重复说明与过大的组件。
- 关闭 Android 滚动边界的整体拉伸效果，改善连续操作和动画闪烁。
- 第四轮用户提出考虑移除总体打分；本轮建议／预览取消第五项总体星级，仅保留选填每日小结，不能称已获生产删除确认。第三轮之前的总体卡和曲线是历史候选。
- 原四项 `5 + 2 × 星数`、补记折扣、等级曲线、任务冻结规则及48枚徽章条件保持。每日小结和周报不新增经验，不从四项均值合成第五评分。
- 当前预览的趋势保留学习／作品／健康／生活四条，不再显示总体曲线，旧空白不能补0星。
- 软件启动后后台检查新版本，有更新时提示并提供下载选项。
- 保留已保存数据；修复账号同步和会话续期。目标为活跃使用持续登录，连续约30天未使用再引导重新认证。
- 首次安装、无登录会话时主动展示可关闭的登录界面，关闭后完整离线使用。
- 推进／完成按钮打开各自精简操作窗；任务卡片空白区域或标题进入完整详情。推进页不出现日期选择，自动使用保存当时的香港当前日期。
- 长期任务创建成功即为「正在进行」，没有推进记录也成立；不自动新增一次推进或增加经验。
- 历史页保持大趋势图、日历与当天回顾、四项依据；右侧改为日期、四项星级缩略、任务进展和小结。新增周报归档，默认已结束周；手机底栏与平板侧栏保持。
- 每日10:00提醒，11:00只在当天无有效业务更新时补发；周一00:00划分并安排生成上周周报，用户已确认周一10:00提醒并与登记合并。系统限制和原生镜像／权限详见专项方案，不在当前安装包承诺已生效。

## 2. 当前可交互预览与排布

[当前预览源](previews/experience-refined.html)默认打开第五轮今日页，可点四项右上角写字图标直接输入、自动暂存、离开输入后在星星下方回看；日历回看／周报归档、通知预览和第二轮任务入口保留。[第一轮候选](previews/experience-refresh.html)只供历史对照。示例只修改预览内存／本聊天状态，不读取真实业务、凭证或触发系统通知。

| 方案 | 排布 | 主要取舍 |
| --- | --- | --- |
| 平板与电脑 | 左侧导航；评分区紧凑，当前任务及进度在右侧；较窄平板将任务紧接评分区 | 保留桌面空间关系，尽量让评分与当前任务同屏 |
| 手机底栏 | 五项固定底部导航；紧凑单列评分，任务接在评分区后；账号入口在页头 | 保留用户选定的操作习惯，底部安全区及键盘避让须真机验证 |

支持四项点星、0星、小结、原因、四条趋势、周报归档／逐日原文／分项指导和50组提醒示例轮播；通知预览可切换10点／条件11点／周一合并并点击进入周报。任务三类入口保持。评分卡不常驻显示未记录或XP范围；示例四项3／4／2／3星共44XP，小结和周报不增加经验。

此处任务、奖励、设置只提供相关排版和入口示意；没有实现真实推进、登录、注册、下载、数据备份或同步。尚未复用全部生产素材和完整成长动效，不能把预览当作新版安装包。

### 建议采用的排布原则

- 按应用窗口有效宽度切换布局，不按「Android」统一套手机底部栏。初始建议：≥1100px桌面完整栏；700～1099px平板侧栏；更窄手机底栏。分屏和横屏按实际宽度重算。
- 平板顶部成长卡控制在约80～96px；缩短页头和日期控件的重复纵向留白，日期与标题在空间允许时同排。
- 四项评分保持同款卡片，平板2×2、手机单列，下面保留独立可选小结；不再把总体星级作为第五张卡。触控区不压进手机半屏。
- 平板／电脑进一步压缩评分卡内边距、页头和备注入口行；右侧优先显示当前任务标题、正在进行状态、进度、截止时间、推进和完成入口，详细规则与额度移入详情。中等平板宽度不强塞两列导致星级触控区变小，改为评分下方的紧凑任务区。
- 紧凑化靠减少空白、折叠次要内容、合并同类操作，不缩小文字和核心触控区。点星、清除、菜单与主要按钮保留约44px触控目标。
- 四项已有记录默认显示在星星下方，卡片随内容自然增高；空内容不占空白区。写字入口直接进入行内编辑，不再用加号折叠。小结默认可输入。
- 任务、历史、奖励中心、设置和二级弹窗同步采用相同密度、对齐与安全区规则。历史趋势不强制横向滚动；软键盘弹出时保证输入可见。
- 手机不承诺五张完整卡片都挤进首屏。以文字可读、触控准确和明显减少滑动为验收目标。

### 2.1 任务操作分层 · 已确定

| 用户点击 | 打开内容 | 不在此处展示 |
| --- | --- | --- |
| 推进按钮 | 精简推进窗：任务标题、任务类型、最多两条最近推进、当前时间、成果说明、取消／保存 | 日期选择、完整历史、删除、归档、原始额度、系数、奖励预估、阶段管理 |
| 完成按钮 | 精简完成窗：任务标题、任务类型、完成时间、成果说明、取消／确认完成 | 完整任务详情与复杂管理操作 |
| 任务卡片或标题 | 完整任务详情：目标、阶段、原计划、历史推进、奖励明细、补记／更正和任务管理 | 不自动触发推进或完成 |

按钮、输入框与卡片入口分别处理事件；点击推进／完成不能冒泡打开详情，键盘也提供对应入口，避免把按钮嵌在另一个按钮中。首页当前任务和任务列表保持相同规则；查看任务历史后返回保留筛选、滚动与草稿。

推进窗的「推进记录」仅为一至两条最近记录摘要，不把全部历史塞进日常操作。必要的标题／类型／时间使用紧凑排列，成果说明以两至三行开始，保存按钮清晰可达。正常字号、常见360／390手机竖屏与平板优先整窗无需滚动；小屏、横屏、系统放大文字、长标题或软键盘占用时允许最少必要的内部滚动，不能裁掉文字或保存按钮来假装不滚动。

推进日期不再可编辑，时间以香港时区显示。打开窗时显示当前时间，**保存提交时重新获取香港当天日期和记录时刻**；跨午夜不能沿用打开窗口时的旧日期。防重复提交、保存失败保留输入，成功后更新当前任务进度并关闭／给予轻反馈。时间是系统记录时间，不新增工时计奖机制；若未来需要记录耗时，另作需求讨论。

补记历史日期和更正仍保留，但只在完整详情中的明确入口操作，继续沿用原日期窗口和补记折扣。精简完成页默认当天；历史完成日期的补记同样在完整详情处理。完成、撤销与任务奖励仍按原冻结C／F、正常额度和实际所得结算，不因拆分入口改变算法。

### 2.2 完整详情与复杂操作 · 已确定

点击任务卡片进入完整详情，集中放置原推进页移出的目标／阶段、计划日期、奖励预估／账本、完整推进历史／单条删除、补记／更正、放弃并归档、恢复／撤销完成、删除整个任务、删除整个任务推进历史等操作。重要信息默认分组折叠；危险操作位于详情内单独区域。

这里的「移出」是保留功能并改变入口，不是删除用户的项目或历史数据。归档和删除须再次确认具体任务、影响范围和经验撤回；整段推进历史清理若需新增批量事务，必须按既有逐条删除语义原子提交，保留取消账本、额度痕迹和持续份额回退，不硬删账本、不补回打折差额、不改写其他任务冻结系数。取消确认不作任何写入。

任务创建成功后，未完成、未归档、未删除的长期任务立即显示「正在进行」，未来计划开始日只是计划信息，不作为「待开始」状态开关；原始start／target及冻结时机保持。旧未推进任务升级后也按同一展示规则显示，不伪造推进、完成或经验。已完成／已归档等状态优先级继续高于正在进行。

阶段任务进度显示已完成阶段／总阶段及对应百分比；无阶段任务显示有效推进次数、最近推进时间，不把已领取XP额度、经过天数或随意估算值当作实际完成百分比。长期任务创建后可以同时显示「正在进行」和「暂无推进记录」，二者不矛盾。

### 2.3 历史记录页面 · 第三轮已确定

所有平台都按同一纵向顺序组织，手机底栏／平板侧栏继续保留，不把日历和大图表并排，也不在大图表前堆叠成长卡、统计卡或重复说明：

1. **顶部大趋势图。** 学习、作品、健康、生活四条0～5星序列，保留7／30天与显示开关。第四轮预览取消总体序列，不合成第五评分。日期为横轴，空白断线、0星零轴有点；窄屏重排标签，XP不混入星级纵轴。
2. **中部日历与当天回顾。** 同宽整体区域，平板／电脑左日历右回顾；第四轮右侧为日期、四项评分缩略、任务进展、原小结，不再放总体卡。手机同区上下排列，日历不单独居中，不嵌套第二层卡片边框；今天／选中／有记录标记及未来日期保护保持。
3. **底部四项评分与依据。** 平板2×2、手机单列；原因原文直接可读、长文本换行、缺失不补0星，整天无记录只显示一次空状态。总体字段不再展示，小结只在回顾区出现一次。

交互联动：打开历史页默认选今天；日历点选日期后原位更新下方全部模块与图表的日期标记，保持页面滚动位置，不整页闪烁或重新播放成长动画。图表点选有记录日期也同步日历与下方内容。仅切换日历月份先改变可见月份，不擅自改写记录；选到图表当前范围外的日期时将趋势窗口移到该日期附近，范围内选择保持原曲线窗口稳定。每条曲线隐藏不改变存储或下方评分。

已有文字默认展开是历史回看样式，不改变内容、结算或原评分参照。补记／更正能力保留于明确的「更正记录」入口，只有用户进入编辑并成功保存才修改业务数据；未来日期保护、补记折扣、原因草稿、失败保留、revision并发检查和保存后真实状态反馈继续按既定规则。新总体字段缺失的旧日期保持空白，不能自动补0星／均值或重发奖励。

原有当天任务事件／结算记录并未删除，可保留为底部评分区域之后的折叠明细入口，避免抢占三个主要区域。回看历史本身允许正常纵向滚动，上一节「尽量不滚动」针对精简推进／完成窗，不要求把大图、完整月历和五项含依据卡片硬塞进手机一屏。

第四轮日历示例使用虚构10月12～18日，周报归档示例使用已结束的9月28～10月4日／10月5～11日，不把尚未结束的10月12～18日称作已发布上周周报。更正、通知和系统权限只示意；归档fixture来自可执行参考算法。

### 2.4 今日四项直接写记录 · 第五轮已确定

学习、作品、健康、生活四项右上角统一改为细线写字图标，触控区域约44px，使用「写学习记录」等无障碍名称。该入口编辑原有的该日该项原因／依据，不新增第二套记录，也不要求先展开菜单、打开弹窗或点第二下输入框。

点击后在同一卡片星星下方立即展开多行输入框，并在本次用户点击内同步聚焦、定位末尾，手机／平板请求系统输入法。输入框使用至少16px文字并随输入增高；键盘出现后保持当前输入可见，真机检查系统返回／收键盘与安全区，不能只以桌面focus检查宣称安卓键盘已验收。

文字在输入时自动保存，不设保存按钮；正式实现建议停止输入约500ms写入，中文拼音／选词composition期间保留草稿、不提交半成品，compositionend后调度。失焦、切换板块／页面、应用转后台时尽力立即落本地；先保留恢复草稿，不能仅靠页面卸载事件保证最后一次写入。不要以异步重绘替换正在输入的节点，避免失焦、光标跳动或打断选词。点击别处／键盘收起后恢复文字展示，写字图标始终可再次编辑。

写完的文字就在原卡片星星下方，保留段落换行、安全转义、长词换行，卡片自然向下延长；无文字时不留空壳。当天返回今日页仍直接可看，不再次点图标、不强制折叠或另建一张卡。历史回看和下次周报沿用同一份原因原文。

保存状态按真实结果显示「保存中／已保存／保存失败，文字已保留，可重试」，本地成功即可反馈，云同步单独排队，不能把云端离线当成本地丢失。保存队列按日期＋账号空间＋维度＋revision序列化，较旧请求不得覆盖较新输入；打开时绑定日期及身份，跨午夜或切账号先处理旧草稿，不将旧文字存进新一天／新账号。原因单独变化不发XP、不改星级、等级、徽章或冻结结算；4000字符沿用现有原因上限，旧长文本完整读回，不静默截断或清空。

目前核心note动作要求先有评分。新版无评分也应允许写记录，先作为不发奖的独立草稿保留，选星后再关联原原因字段，不能为了保存文字自动补0星或触发基础奖励。正式数据字段需在旧JSON往返／导入兼容检查后定；现有评分的note及已有原文必须继承。清空文字只清该原因，不能删除星数、其他板块或奖励。

**当前预览范围：**输入后立即更新示例内存，中文选词结束后才提交；失焦显示正文，切今日／历史可回看。有限聊天状态快照仅尽力恢复，超过16KiB不提交快照，输入仍在本次预览内存中；标注「自动暂存·示例预览」，没有冒充应用本地事务、云同步或退出后持久化。预览不读写生产IndexedDB，不弹系统通知；Android实际输入法、保存失败恢复、午夜／账号切换和旧数据兼容仍待正式工程验收。

| Windows会话 | 加密文件恢复通过setSession；persist基于getSession；尚无本应用统一的30天闲置策略 | 梳理SDK自身刷新和令牌轮换写回，增加统一、可测试的活动与续期策略 |
| Android会话 | SDK存储放内存，加密保存session/storage/deviceId和已验证identity；有刷新事件持久化 | 检查恢复后过期令牌／新refresh token落盘、并发写入顺序、进程杀死与休眠恢复 |
| 数据继承 | 访客`current`与`account:<uid>`隔离；已有手动「复制未登录记录」 | 先区分显示到另一个命名空间还是数据缺失；不能直接覆盖或盲目合并 |
| 推进入口 | `quick-progress`先打开完整taskDetail，再滚到progress-form；该表单有日期选择 | 拆出独立精简推进窗，详情保留历史补记入口 |
| 任务状态 | 当前taskStatus以是否存在有效推进决定「进行中／待开始」 | 活动长期任务从创建即显示正在进行，不更改奖励或进度账本 |
| 更新与系统通知 | 当前依赖／生产入口未接入更新检测或远程推送；Android清单只有INTERNET权限 | 先发布具备检测功能的新版本，不能声称旧包会收到应用内更新提醒 |
| 历史页布局 | `historyPage`当前将calendar和trend放在history-overview；下方四项评分及当天任务事件 | 改为图表、紧凑日历、所选日评分纵向分区；增加总体回看，原因默认显示，任务事件折叠保留 |

这些事实不等于已复现用户当前账号故障。需要结合隔离验收与用户设备现象确认；当前未读取用户业务快照或云数据。

交接记录中存在此前按用户授权清理云账号的历史；相同邮箱重新注册不保证UID相同。不得据此推定用户当前数据已删除，也不得仅按邮箱、显示名或本机记忆将其他UID的数据归入新账号。

## 4. 历史候选：今日总体评分数据设计（第四轮建议移除）

本节保留第三轮方案背景，不作为当前预览实施指令。第四轮建议只保留每日小结；新参考算法忽略总体星级、兼容候选小结文本，正式字段与兼容策略见[提醒与周报方案第8节](提醒与周报详细方案.md#8-数据兼容与总体打分退场)。没有执行真实数据删除。

建议新增独立的按日记录映射`dailyReviews[YYYY-MM-DD] = { stars: 0..5 | null, note, updatedAt }`，不加入固定`DIMENSIONS`，不写奖励账本。允许只写小结而不选星；空白与0不同。选星、修改、清除、删除小结都只影响该日记录，不触发经验、等级和徽章奖励。

日期沿用香港时间，支持历史补记与更正，未来日期禁止。无经验就没有总体评分补记扣分；不能把它当成第五项奖励维度。现有四项日完成标记保持；总体卡单独显示自己的记录状态。

### 兼容与同步

1. 保留数据库名、页面来源、包标识、账号namespace、Android证书和安装数据路径。
2. 旧快照缺少新映射时在副本规范化为空；旧账本、冻结参数、processed、revision及modifiedAt保持语义，不重算、不重发经验。
3. 新字段必须随本地保存、导出／导入、云快照和跨端回读完整保留，并严格校验日期、0～5整数／空值、文本上限和时间。
4. **不能仅说「可选字段所以兼容」**：上线前验证现有旧客户端读写新字段的实际行为。若旧端会丢字段，需要升级备份格式或添加能力／最低版本保护，旧端拒写新格式；迁移前保留完整原始副本。规则1.3不因新增无经验记录而改变，JSON格式最终编号由兼容试验确定。
5. 重复导入、云下载、版本升级不播放历史成长奖励。损坏记录拒绝替换，保存失败保留输入草稿。

趋势新增独立的总体星级序列，空白断线、0星显示在零轴，支持7／30天与单日小结回看。周期均值只除以实际有星级记录的天数，小结不自动算作0星。

## 5. 长期登录与同步修复

### 目标行为

访问令牌短期有效，依靠refresh token续期；不将访问令牌本身强行延长一个月。启动、恢复前台和即将过期时刷新，会话失效的请求只尝试一次受控刷新和重试，避免死循环和并发刷新互相使令牌失效。新的轮换凭证串行、原子地加密落盘；Windows和Android共享相同的状态定义和测试情景。

「30天未使用」指连续30天未在前台使用应用；更新活动时间需节流，后台定时同步不能无限延长闲置窗口。退出、修改密码／服务端撤销或实际refresh token失效仍需要重新认证。首次从旧会话升级时补充活动元数据，不把缺字段一律判为已闲置30天。

客户端能实现上述流程；实际持续登录上限还依赖CloudBase当前环境的刷新令牌策略。实施时必须读取非秘密的实际策略并测试；服务端若提前到期，需在已授权范围调整相应配置或如实报告限制，不能用本地登录标志伪造有效认证。

状态应明确区分：已同步、同步中、离线待同步、需要重新登录、服务暂不可用。无网络／暂时刷新失败不清除本机业务数据，也不把网络错误当作用户主动退出。离线展示既有账号记录不代表持有可调用云端的有效身份。

### 继承与上传保护

- 初次登录先读取并完整校验云快照，再确定本机账号快照的处理方向。云端与本机各自有内容时先保存双方恢复副本，再沿用现行较新快照策略；时间不可信或UID有歧义时提供明确的数据选择，不静默覆盖。
- 仅访客有记录且云端／账号确实为空时，可以引导将已有记录继承到已验证的当前账号；有两份内容时不直接合并账本或覆盖。原访客快照仍保留。
- 新邮箱如对应已有账号，只验证身份和读回，不灌入测试业务数据。当前账号的数据核查另用只读、数量／revision／UID匹配结果，报告不公开个人数据。
- 保留现有上传requestId、版本CAS、revision检查和上传期间新修改排队；账号切换时旧请求不能落入新账号。
- 任何需要用户真实凭据的验收由用户正常登录完成，不从本机账号或历史材料推断密码／邮箱，不记录明文凭证。

## 6. 首次启动登录引导

启动顺序：打开本地快照并恢复加密会话 → 展示应用 → 无会话且本安装尚未展示引导时打开可关闭登录框。启动动效完成后再显示，避免登录框被遮挡；恢复身份暂时超时不能闪现错误的登录要求。

提供「登录」「注册账号」「暂不登录，直接使用」及关闭按钮；关闭立即继续离线记录。安装级引导标记独立于业务备份，正常更新、导入、切页不重复弹。清除应用数据后视为新安装。会话30天闲置／撤销后的登录提醒单独处理，同样可关闭并保留离线使用。

首次安装的未登录界面立即体现登录入口，不让网络检查或云端错误阻塞本地使用。具体启动动画与引导的先后在真实双端验收时调整，功能目标以用户要求为准。

## 7. 启动检查更新

启动立即发起独立后台检查，网络超时不阻塞输入；发现**当前平台应用版本**更高时，在启动／已有弹窗结束后提示「当前版本还有最新版本」，展示当前／最新版本与「下载最新版本」「稍后再说」。

发布来源固定为已授权公开仓库`StuTuse/rater-tracker`。现有Release是prerelease，`releases/latest`不能作为唯一入口；读取发布列表并识别非Draft候选。Windows和Android版本独立比较，不能把日期批次tag或源码Release当作应用升级。建议后续Release附机器可读的更新清单，明确两端版本、下载URL、摘要、最低读取能力和未变端包来源，现有Release不修改。

纯文档Release不提示应用升级；未变端引用原包；预览用户可检测更高alpha，稳定渠道策略另按将来的正式发布要求确定。一次运行对同一版本只提示一次，关闭后保留设置页入口。

选择下载才打开明确的官方Release或对应包链接，不静默安装、不修改用户业务记录；Windows／Android各按现有安装流程覆盖更新。联网失败安静重试；仅用户主动检查时显示失败说明。真实下载路径、来源校验、摘要与升级数据保持须单独验收。

### 已安装用户能否收到更新消息

**可以建立通知能力，但已经装好的旧包不会因为服务器发布Release就自动拥有新功能。** 当前Windows alpha.21／Android alpha.6尚未接入应用更新检测／远程推送，需要用户先手动覆盖安装一次带检测能力的新版本；沿现有安装包路径／包名和Android原证书升级，按兼容验收保留数据。之后启动、恢复前台及应用活跃时周期检测即可显示应用内更新提醒，不要求登录账号。

| 情形 | 能力与安排 |
| --- | --- |
| 现有旧版本 | 无法直接通过应用给所有安装用户发通知；可以公开发布下载页，用户自行访问。若用户自愿在GitHub订阅Release，可由GitHub按其通知设置提醒，不等于应用推送 |
| 已升级且软件运行中 | 启动／前台／适度周期检查版本清单，显示应用内提示；按平台和版本去重，文档Release不重复提醒 |
| 希望通知中心也有提醒 | 后续可选接入Windows原生通知、Android通知权限和渠道；通知被拒绝时仍保留应用内提醒。点击通知打开版本说明或下载入口 |
| 软件已完全退出或设备离线 | 当前不承诺实时送达。系统通知显示能力不等于远程推送；需要另行设计后台任务／系统调度或推送服务、设备注册和权限。Windows现有关闭即退出语义保持，不能偷偷加常驻服务；Android后台受系统限制也不能保证即时 |

建议本轮优先交付「一次手动升级 → 后续自动检查并在应用内提示」，把完全退出后的系统推送列为可选后续范围；用户本次问可行性，不据此发送通知／邮件、索取所有用户联系方式、自动申请通知权限或创建新外部服务。通知文案、权限开关、去重、网络／系统拒绝和点击行为需要独立验收。

官方依据：[Electron通知与Windows条件](https://www.electronjs.org/docs/latest/tutorial/notifications)、[Android 13及以后通知权限](https://developer.android.com/develop/ui/compose/notifications/notification-permission)、[GitHub自定义订阅Release](https://docs.github.com/en/subscriptions-and-notifications/how-tos/managing-subscriptions-for-activity-on-github/managing-your-subscriptions)。

## 8. 动画处理与验收

- 原生WebView禁用overscroll，CSS同时覆盖正文、弹窗与内部滚动容器；保留正常滚动、输入选择及系统返回。
- 星级与经验从当前可见帧接续，快速连点取消旧反馈但不取消业务保存；优先transform／opacity，避免反复布局和阴影／滤镜大面积重绘。
- 页面切换只播放新内容组一次；保存、文字输入、同步回读时不让整页反复淡出／淡入。保留焦点、展开状态、草稿与滚动。
- 页面不可见暂停装饰动效，回来直接落到真实保存值；系统减少动态和完整／柔和／关闭偏好继续有效。
- 不承诺仅靠CSS修改达到固定FPS。用实际Android渲染、帧记录和连续操作观察确认，记录设备和检查范围。

| 验收组 | 关键场景 |
| --- | --- |
| 布局 | 360／390手机、700／800平板、横屏／分屏、桌面；200%文字、长备注、软键盘、安全区、无内容横向溢出 |
| 越界 | 顶部／底部快速拖动、短页面、长页面、弹窗嵌套滚动，内容不整体拉伸 |
| 评分兼容 | 旧备份、缺新字段、新字段往返、0／空白、只记小结、补记／删除、四项原账本和XP逐项一致 |
| 动画 | 连点增减星、切页／返回、保存与云回读重叠、升级与撤销、减少动态，不闪空、不阻塞输入 |
| 会话 | 访问令牌到期、刷新轮换后杀进程、离线一两天再开、前台跨日、30天闲置、撤销、网络失败、UID不匹配 |
| 同步 | 访客→空账号、有云数据、两端离线修改、上传中再保存、切账号、重试同requestId，不重复结算或误覆盖 |
| 更新 | 两端独立版本、纯文档Release、预发布、无包／坏清单／离线、关闭／下载、覆盖安装后原记录保持 |
| 引导 | 新安装无登录主动打开、关闭正常使用、注册／登录、升级不重弹、会话恢复不闪误提示 |
| 任务入口 | 卡片打开完整详情；推进／完成按钮各开精简窗且不冒泡；创建即正在进行；按阶段或有效推进记录正确显示进度 |
| 推进窗 | 常规手机／平板不滚动、无日期选择、当前香港日期、跨午夜保存、失败保留草稿、连点只保存一次；大字号／键盘不遮挡保存 |
| 任务管理 | 完整详情保留补记与历史操作；归档／取消／单条及整段历史删除按原冻结和撤回规则验收，不丢旧记录 |
| 历史回看 | 图表→日历→评分固定顺序；点日期／曲线联动星级、小结与四项依据；0和空白、整天无记录、总体缺项、7／30天、月切换、长文本和手机布局；回看不触发奖励或修改 |

建议实施顺序：先讨论界面选型 → 用隔离数据验证兼容和会话 → 实施共享组件与Android适配 → 双端真实渲染及打包验收 → 沿原证书和既有发布流程发布。账号续期和同步排查可与界面讨论在同一会话推进，不派遣其他会话。
