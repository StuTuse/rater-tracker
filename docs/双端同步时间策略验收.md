# 双端启动同步与修改时间策略 · 2026-10-15

Windows `0.1.0-alpha.19`；Android `0.1.0-alpha.4`／VERSION_CODE=4；产品v1.25，结算1.3／JSON1。

## 原问题与实际修复

旧启动路径先显示本机快照；同步引擎发现dirty／inFlight时先上传，上传冲突后停止，未继续读取云端。旧快照没有统一修改时间，无法按最后修改自动选择。

现在恢复账号即后台启动pull；读取返回后获取最新本机状态并比较时间。本机账号每次成功保存附带ISO modifiedAt，单机时间至少递增1毫秒，随完整JSON同步。云端较新则校验并原子替换本机，包括清除旧待上传；本机较新即上传，即使旧dirty标记未设置。请求以刚读取的云版本作CAS；过时inFlight替换为当前快照。云版本上传期间再变化时重新读取，连续3次冲突后等待后续自动检查，不无限循环。相同云版本／时间的周期检查不增本机revision、不重放奖励。云端失败继续使用本机，并保留待传状态。

比较完整快照，不合并两份账本。历史无修改时间的云快照按cloud version与baseVersion兼容判断；无法恢复旧客户端从未记录的真实修改时刻。修改时间来自设备时钟，两端需升级此次版本以保证之后每次写入都会更新时间。云端RPC参数及身份隔离不变，完整state JSON保存新增可选字段；备份格式仍1，下载和恢复不重算旧结算。
