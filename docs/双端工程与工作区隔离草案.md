## 已核实的起点

- 当前 Windows 版本为 0.1.0-alpha.17，主分支 main，HEAD 为 ecf790f；开始本轮时工作区干净。
- Git 只有当前一个工作目录，无远程配置。本轮不创建、派遣或消息通知其他会话。
- 原生 HTML/CSS/JavaScript + Electron；src/core.js 已独立实现整数 micro-XP、香港日期与纯业务事务。
- src/storage.js 包含 IndexedDB 保存与备份校验，src/sync.js 实现完整快照同步；账号与文件接口仍包含 Electron 平台分支。
- 正常 Windows 数据路径为 %APPDATA%/RaterTracker；现有开发验收快捷方式和安装版共用正常数据，不能直接作为隔离开发入口。
- 账号来源限制与安卓真实认证尚未验证；窄屏浏览器历史检查不等同于安卓安装验收。

## 建议：一个仓库、两个应用工程、独立工作目录

建议保留现有本地 Git 历史，以单仓库管理共享规则和资产，Windows 与 Android 分别拥有应用入口、原生壳、构建配置及交付版本。需要并行编码时，各工作目录使用不同任务分支及 Git worktree。

“工程拆分”负责代码边界，“worktree”负责并行修改的文件与暂存区隔离。各 worktree 都是自己的源码副本；共同代码的修改需要提交、审查、合并后才传到另一工作区，不实时共享。提交对象、分支和标签仍属于同一仓库；同一分支不在多个工作目录同时检出。

目标结构示意（当前尚不存在）：

```text
apps/
  windows/      Electron、桌面入口与专用布局、安装构建
  android/      安卓原生壳、移动入口与专用布局、APK 构建
packages/
  core/         唯一结算、日期、等级及徽章判定
  data/         快照契约、校验、备份与同步协议
  ui/           可共用控件、视觉变量及动效
  assets/       48 枚徽章、插画、图标等源资产
cloud/          共同后端与迁移
docs/           权威规则、各端交接与验收
```

数据契约可以共用，具体保存、文件选择、凭证加密和生命周期通过平台适配接口实现。移动布局可以独立演进，适合复用的界面组件再共享，不要求桌面与手机保持同样排版。

当前目录保留 main 作为集成基线；Windows 开发和 Android 移植分别使用独立 worktree 与 codex/ 前缀任务分支。实际路径在建立时登记，不在讨论文档中声称已创建。先做隔离，再单独完成可验证的结构拆分，之后双端继续各自开发。任务分支完成后集成，避免两条平台分支长期分叉。

若用户要求两个完全独立 Git 仓库，可改用第三个共享核心包并锁定版本；代价是共享规则发布、升级与三处维护，不能仅复制现有工程后各自维护结算。

## 同时开发的约定

| 范围 | 负责与集成原则 |
| --- | --- |
| Windows 专属入口、Electron、安装配置 | Windows 负责范围，独立提交与桌面验证 |
| Android 专属入口、原生插件、移动布局、APK | Android 负责范围，独立提交与设备验证 |
| 规则、快照格式、共享 UI、资产、云端迁移 | 明确一个集成负责人；提前在文档登记，提交后按依赖顺序同步 |
| 交接与验收 | 各端独立记录，根交接只记录集成状态与共享变更 |

用户可以分别在两端工作目录打开自己的开发聊天；本轮不自行创建其他聊天。共同文件的变更登记不是文件锁，需要同时修改时协调或等待集成，不能直接覆盖另一工作目录。

每次完成改动先做对应端检查；涉及共同规则或数据时，两端都验证后再进入 main。一个平台的版本更新不要求另一个平台同时发布。现有 Windows 标签保持；未来安卓使用平台明确的版本和附注标签，共享规则与格式独立编号。具体 VERSION 入口在结构拆分时确定，当前 VERSION 不变。

## 隔离范围

1. 源码与 Git：独立目录、任务分支、暂存区；不在共用目录各自切分支。
2. 依赖与输出：各 worktree 的依赖安装、预览端口、报告及构建输出独立；系统 SDK 缓存可共用。
3. 本机数据：Windows 隔离开发入口使用独立 userData；Android 开发包使用区别于正式包的应用标识和私有数据空间，后续正式包保持稳定标识以支持升级。
4. 云端数据：开发入口使用测试账号或可用的独立测试环境；不默认登录个人账号。云端迁移统一集成，不让两个工作区分别执行。
5. 签名与私密材料：不入库；正式安卓签名密钥需持久保存以支持后续更新，不能每次构建换密钥。

## 安卓移植建议及验收边界

建议优先验证 Capacitor + Android 原生壳，保留现有 JavaScript 结算与视觉资产；这是技术建议，尚未安装依赖或选择具体版本。官方文档支持将既有 Web 工程及打包的界面资产加入 Android 项目。

先验证最小 APK、持久化与 CloudBase 认证可行性，再实施完整移植。Electron 的 Node SDK、IPC 与 safeStorage 不能直接搬进安卓；应实现适合安卓的认证、文件与凭证接口。CloudBase 官方文档要求 Web SDK 配置安全来源，现有环境是否支持安卓的具体接入方式需实际验证，不能因为桌面成功就承诺安卓成功。不得通过管理员凭证入包绕过限制。

完整交付应覆盖现有五页、评分与任务完整事务、48 枚徽章、十阶段成长、动效偏好、账号流程与同步、本地保存、完整 JSON 导入导出。针对触控、软键盘、返回键、系统栏、前后台与进程重启分别适配；构建成功、390px 浏览器检查或模拟 UI 不能代替安卓安装与运行验收。

跨端数据沿用完整快照、版本检查与冲突保留；两台离线设备同时修改依然可能冲突。本次工程并行不意味着自动合并两端账本。Windows/Android 互导与同步应保留原冻结参数、不重发奖励，并实际验证离线、重启、覆盖安装、保存失败及冲突。
