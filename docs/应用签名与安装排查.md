## Windows：SmartScreen尚待受信任签名

旧alpha.20和本次作者信息更新的alpha.21安装包均回读`Authenticode=NotSigned`。本机CurrentUser／LocalMachine个人证书库未发现可用代码签名证书，常用证书／云签名环境配置未设置。alpha.21的EXE和Setup中`CompanyName=TuseCreation`、版权为`Copyright © 2026 TuseCreation`；作者元数据不能提供操作系统认可的签名身份。

额外只读检查：桌面当前“开发验收”快捷方式指向本机缓存的未签名Electron，目标EXE未带Zone.Identifier；本轮未更改该快捷方式。后续取得签名身份时，需要确保实际使用的是已签名安装程序及应用，而不能只为一个未被该快捷方式使用的包签名。

已提供`npm run dist:signed`，通过electron-builder的`forceCodeSigning=true`要求应用实际签名。使用已有证书时，在本机私有环境配置`CSC_LINK`和`CSC_KEY_PASSWORD`，或接入证书提供商支持的签名方式，再运行该命令；不要把私钥或密码提交到Git。本次实际执行强制签名构建，在缺少证书时按预期失败，没有把未签名包冒充签名包。`npm run dist`仍可生成明确标注的未签名预览。

后续需要受信任CA证书／云签名身份，或Microsoft Store的MSIX分发。受信任签名也不承诺每个新版本立即免除SmartScreen信誉提示；显示的验证发布者取决于证书身份。依据：[微软代码签名说明](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/code-signing-options)。本轮没有安装自签根证书或更改系统防护设置。

免费开源签名选择SignPath Foundation路线，但仍需审核，其证书发行主体为SignPath Foundation；仓库公开不自动等于符合条件。用户已接受MIT及该证书主体，源码现有根LICENSE；申请尚未提交。依据：[SignPath条件](https://signpath.org/terms.html)。

已准备[接入方案](免费开源签名接入方案.md)、[申请资料](SignPath申请草稿.md)、[Code signing policy](CODE_SIGNING_POLICY.md)与[隐私说明](PRIVACY.md)，并提供主分支手动未签名样包工作流。用户自行在表单填写姓名和邮箱；尚未提交申请、接入签名服务或改动现有Release包。

## Android：增加兼容签名并阻止未签名发布

旧alpha.5 APK通过官方apksigner的v2验证，因此用户手机提示不能直接等同于该发布包完全未签名。alpha.6显式启用v1／v2／v3，保持既有密钥与证书不变；指纹为`648b3a169d4b63da50312f44fc09241e8e796a39b781baa60e48a42719c60448`，证书组织为TuseCreation。没有为了改名换证，避免破坏覆盖更新。

Android最低系统仍为API24（Android7.0）。默认按API24验证时，apksigner可能跳过v1并显示v1=false；新的校验分别运行默认验证和API23限定的JAR签名验证，后者只检查v1密码学兼容性，不代表支持Android6。依据：[apksigner](https://developer.android.com/tools/apksigner)、[Gradle签名配置](https://developer.android.com/reference/tools/gradle-api/8.13/com/android/build/api/dsl/ApkSigningConfig)。

构建规则：

- `npm run android:build`要求恢复既有私有签名配置，缺失时立即停止，不自动生成新身份；直接Gradle release任务也必须通过`requireReleaseSigning`。
- `scripts/android-verify.mjs`调用SDK内apksigner与aapt，强制验证三种签名、原证书指纹、正式包名和当前版本，成功后才复制正式APK并产生验证报告和SHA-256。
- 公开的`apps/android/signing-identity.json`只保存产品署名、包名和公开证书指纹，不含私钥或密码。

实际命令（项目根目录）：

```powershell
npm run android:build
npm run android:verify
# 也可核验明确文件，必须符合当前正式版本与签名策略
npm run android:verify -- "release/android/Rater-Tracker-Android-0.1.0-alpha.6-release.apk"
```

JDK21通过`RATER_JAVA_HOME`或忽略目录`runtime-data/toolchains`定位；SDK通过`ANDROID_SDK_ROOT`／`ANDROID_HOME`或本机默认SDK定位。构建默认使用忽略的`runtime-data/android-gradle-home`和`runtime-data/android-tmp`，解决本次环境系统缓存／Temp不可写的问题。`RATER_BUILD_PROXY`只在实际下载需要时设置。
