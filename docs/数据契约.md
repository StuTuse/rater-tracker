# 0.1 数据与结算契约

日期：2026-10-13，香港时间。本会话集成负责人负责全部共享规则／数据入口。产品文档 v1.9，结算规则仍为 1.3。

## 金额与时间

- 内部金额单位为 `1 / 1,000,000 XP`，全部金额保存为非负安全整数。百分比乘除经 BigInt 有理数运算，每笔分配只做一次四舍五入；界面一位小数不参与回退。
- E 以整数金额冻结；C 以百分之一保存，例如 108 表示 1.08。持续奖励每个 2% 份额独立保存，避免回退时重复计算或替换旧折扣。
- 折扣保存 `{ numerator, denominator, delay }`：及时为 1/1；延迟 d≥1 为 5/(d+9)。评分前一天在香港 04:00 前适用宽限，任务严格自然日。
- 事件日期是 `YYYY-MM-DD`；记录时间为 ISO 时刻。业务日期经固定 +08:00 计算，不依赖 Windows 当前时区。
- 极微量的四舍五入差额以实际入账整数为准；反复取消不会产生浮点尾差。

## 快照格式 1

`createState()` 生成 `{ format, rule, revision, sequence, ratings, tasks, ledger, processed, settings }`。

| 数据 | 保存内容 |
| --- | --- |
| `ratings[date][dimension]` | 0～5 星、选填文本、基础结算 ID、每颗有效星的批次 ID |
| `tasks[id]` | 原／当前日期、名称、成果、类别、重要性、阶段、创建结算、冻结计划、推进、完成／撤销历史、归档／隐藏／删除标志 |
| `frozen` | 原 start/target、真实 D、E、量级、重要性、规则版本 |
| `progress[]` | 唯一 ID、实际日期、录入时间、成果文本、结算关联、有效状态、正常额度是否保留 |
| `completion` | 日期、录入时间、结算顺序、所属窗口、冻结 C、基础结算、持续份额、有效状态、撤销自然日 |
| `completionHistory` | 已取消的旧完成快照；不用于追溯重写其他任务 |
| `ledger[]` | 唯一 ID、来源、类型、实际日期、记录时刻、正常额度、冻结 F、实际所得、规则、结算顺序、有效／取消信息 |
| `processed[]` | 已成功事务的唯一操作 ID，保证同一操作不重发 |
| `settings` | 动效、四项评分参照、最近导出时刻 |

取消明细保留原正常额／实际额，切换为 `active=false`。总经验只汇总有效实际所得；等级与星数／任务徽章都从当前同一快照派生。

## 更正与冻结

评分基础与每颗星分别入账，减少星数优先取消最近批次。历史增星使用本次 F，旧批次不重算。文字事务不分配经验。

任务首次推进或直接完成冻结计划。推进的正常额度累计最多 0.5E，创建 2 XP 独立包含于 E。完成基础结算为 `E×C − 创建正常额 − 已分配推进正常额`；持续部分以最多十个 `E×C×2%` 份额补齐。两者合计符合正式方案 T。

历史／已完成推进删除后，其正常分配仍保留于额度累计，实际所得撤回；有效持续日真正减少时撤回最近有效份额。未完成且尚无完成历史的当日误记录删除，可释放其额度。完成后补录只产生持续份额，不再预付。

同日恢复同一实际完成日期，沿用原 C 和可恢复份额的原 F；已经因其他更正取消的份额不恢复。跨日重新完成创建新结算，旧完成仍取消。删除整个任务只取消它的有效明细，避免重复扣关联奖。

## 保存与冲突

IndexedDB 数据库 `rater-tracker`，object store `snapshots`，键 `current`。完整业务更正先在纯函数副本计算，再在一次 readwrite 事务里检查 `revision` 并保存。事务成功前不更新经验／等级／徽章反馈。

同页面保存串行。旧页面的 revision 不一致会中止写入，载入新快照并提示重试；不会覆盖新记录。保存失败保留输入，显示本次未保存。页面动画与业务分离，不能发奖或影响事务。

## alpha.6 账号同步补充

IndexedDB 仍为格式 1、snapshots store；原 current 保留未登录记录，账号使用 account:<uid>，同步元数据使用 account:<uid>:sync。写业务数据与 dirty 标记在同一读写事务中完成。云端版本 baseVersion 与业务 revision 分开；inFlight 保存稳定 requestId、原上传 state 和 baseVersion。确认后仅清除已发送的本地 revision；新输入继续 dirty。conflict 阻止自动覆盖，显式下载前先完整导出本机备份，并检查本机 revision 没变化。

CloudBase PostgreSQL 表 rater_accounts / rater_receipts 为私有存储，客户端没有直接读写权限；rater_sync RPC 显式要求 authenticated 身份，owner 从 auth.uid() 取得。行锁、版本 CAS 和回执同事务；重复请求不重写。同步完整快照不重算结算；容量限 4 MiB。下载仍经 validateState 完整校验。服务端 RPC 只检查基本格式和容量，不作为备份真实性／奖励防作弊证明。

Windows account-session.bin 仅保存经 safeStorage 加密的认证会话及显示名称；无加密能力时只保留内存会话。账号密码不写入业务快照或日志。alpha.7 账号注册接入官方邮箱验证，验证回调只在进程内暂存，向界面仅返回流程ID和邮箱；有效期10分钟，成功／退出清除，关闭浮层清空密码输入。验证码错误可重试，不能凭未验证注册取得账号身份。密码重置仍在 CloudBase 控制台完成。原离线模式规则和备份结构不变；云端整份替换通过版本检查，不实现操作级合并。

## 备份与升级

完整 JSON 包装为 `{ application: "rater-tracker", format: 1, exportedAt, state }`。导入校验格式／规则版本、ID、日期、整数金额、F 与实际金额、记录关联、有效状态、评分批次和设置；限制 64 MB。校验不是数字签名，不用于证明备份来源。

导入预览数量和评分日期范围，先成功导出当前备份，再完整替换。恢复只将 revision 设为当前 revision+1，防止旧页面覆盖；不调用奖励事务，不重演历史成长动画。重复导入的业务内容和有效总数一致。

桌面正常 `userData=%APPDATA%/RaterTracker`，来源固定 `app://rater`；升级沿用 appId `local.ratertracker.desktop`。格式迁移尚未实现，未知格式拒绝读取／导入并保留原数据，不猜测或重算历史。
